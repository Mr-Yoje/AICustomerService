**智能催收对话引擎 Agent 赛题说明**

面向参赛者发布版

# 一、赛题背景

智能催收是金融智能语音平台的核心产品之一。在消费金融、信用卡、小额贷款等业务中，逾期客户催收是一项高频且合规要求极严的工作。传统催收依赖人工坐席，存在话术不规范、情绪失控、违规时段外呼、频次超限等合规风险，同时坐席人效低、还款意愿评估主观化。本赛题提供一套模拟金融催收业务数据集，参赛团队需基于该数据集构建智能催收对话 Agent，实现合规催收对话、还款意愿评估、分期方案协商、情绪感知与人工接管无缝切换等全流程能力。

# 二、任务目标

- 基于官方模拟金融催收业务数据集，建立可对话、可评估、可解释的催收决策层。
- 支持自然语言多轮催收对话，能够识别客户还款意愿、情绪状态与意图变化。
- 根据客户画像与历史行为，输出还款意愿评分与推荐催收策略。
- 在合规规则约束下生成分期方案，并能就期数、利率、手续费进行协商。
- 实时检测合规红线（辱骂、威胁、违规时段、频次超限、虚假承诺等），触发人工接管。
- 输出催收话术、评估报告、合规审计日志与协商记录，全过程可追溯。

【注意】不能直接基于多个csv文件直接做简单LLM应用结果输出，要构建Agent系统，支持数据导入、解析、分析、解释、决策、可视化等完整流程。

# 三、必选功能

| 功能 | 要求 |
| --- | --- |
| 多轮催收对话 | 覆盖提醒、施压、协商、确认等典型催收话术，支持上下文记忆与意图切换。 |
| 还款意愿评估 | 结合客户画像、逾期信息、历史行为，输出还款意愿评分（0-100）与依据。 |
| 合规红线检测 | 实时识别辱骂、威胁、违规时段（22:00-次日8:00）、频次超限、虚假承诺等违规。 |
| 分期方案协商 | 基于欠款金额与客户承受能力，生成分期方案并支持多轮协商调整。 |
| 情绪感知 | 识别客户情绪（愤怒、焦虑、抵触、配合等）并随对话动态更新。 |
| 人工接管 | 触发合规风险或客户强烈拒绝时，平滑切换至人工坐席并移交上下文。 |
| 催收报告 | 单次催收结束后生成评估报告，含还款意愿、建议策略、合规审计、协商记录。 |

# 四、数据说明

本赛题使用官方提供的模拟金融催收业务数据集。数据为模拟生成，不涉及真实个人金融信息或商业秘密，所有客户姓名、身份证号、手机号均为脱敏虚构数据。参赛团队应基于官方数据包完成开发、演示和自测。

## 数据包内容

| 文件 | 类型 | 说明 |
| --- | --- | --- |
| dim_customer.csv | 维表 | 客户画像，包含客户ID、姓名（脱敏）、年龄、职业、月收入、信用评分、区域、客户等级。 |

| fact_overdue.csv | 事实表 | 逾期信息，包含逾期ID、客户ID、贷款ID、欠款金额、逾期天数、逾期期次、最近还款日。 |

## 测评集说明

- **公开测评集（含标准结果，可自测）**：随参赛资料一并下发，文件为 `公开测试集答案.csv`，含每道评测场景的标准答案，**可用于提交前自测**；评委亦会从中现场抽样，要求系统即时处理并与标准结果逐项比对。
- **非公开测评集（只含输入、不含结果）**：**赛前不下发**，现场由评委提供只含输入、不含结果的材料，当场检验系统的泛化能力与新增场景的适配成本。

# 六、评审要点概述

> 本节只给出评审关注的**四个一级维度**与希望做到的方向。**详细评分标准与分值由评委掌握，不向参赛者公开。**

## 6.1 四个维度的评审要点

| 维度 | 会看什么 | 希望做到什么 |
| --- | --- | --- |
| **① 评测集表现** | 系统在给定催收场景上的对话输出：意图识别、话术质量、合规判别与报告结论 | 输出与标准结果一致，能**现场实时重算**；结果是系统跑出来的，而不是预录或硬编码 |
| **② Agent 工程架构完善度** | 记忆系统、会议与资产管理、工具调用能力、Skill 管理四项通用工程能力 | 见下方四条通用要求 |
| **③ Agent 通用评测（鲁棒性、可解释性）** | 异常输入与长任务下的表现，以及结论的推理过程 | 见下方两条通用要求 |
| **④ 合规性** | 敏感数据的处理方式，以及输出内容的合规性 | 见下方两条通用要求 |

**② Agent 工程架构完善度 —— 四项通用要求**

- **记忆系统**：能跨轮次记住已确认结论与口径（如客户还款意愿、已承诺的还款安排）并在后续对话中正确复用；记忆内容可查看、可纠正、可清除。
- **会议与资产管理**：能对任务、待办与产出物（对话记录、催收报告、审计日志）进行建档、检索、状态跟踪与归档，形成完整闭环，而不是静态展示。
- **工具调用能力**：工具选型正确、参数构造准确、无冗余调用；调用失败可诊断并正确重试或降级，返回结果被真正用于影响后续结论。
- **Skill 管理**：能把重复任务（如"执行一条合规红线检测""生成一份分期方案"）封装为可复用 Skill／工作流，具备明确的触发条件与输入输出契约，可跨任务迁移复用。

**③ Agent 通用评测 —— 两条通用要求**

- **鲁棒性**：异常输入（乱码、空输入、意图冲突、极端值、超长或乱序对话）**不崩溃、不静默出错**；外部调用与长任务有超时控制，超时后明确告知并给出可执行的下一步；失败可自动重试且单点失败不导致整体流程崩盘。
- **可解释性**：结论能给出依据与推理过程——指出命中的合规规则编号、涉及的逾期记录、金额、时间、记录 ID；可展示中间过程而非只给答案；对不确定项给出置信度并标注"需人工复核"；同输入多次运行结论一致、格式不漂移。

**④ 合规性 —— 两条通用要求**

- **数据处理合规**：**敏感数据不外送**，确需调用外部大模型或服务时先完成脱敏；界面展示、运行日志与导出文件中的敏感字段同样脱敏，外部调用可审计。
- **输出内容合规**：输出无不当表述，对客户的不当表述能恰当处理；**法规条款不编造**——政策、法规、条款、标准编号与条文内容不得幻觉生成，更不得以此作为结论依据；违规时段、频次超限、虚假承诺等红线应被稳定识别并触发人工接管。

## 6.2 评测集说明

- **公开测评集（含标准结果，可自测）**：随参赛资料一并下发，**含标准结果**，可用于提交前自测；评委亦会从中现场抽样，要求系统即时处理、与标准结果逐项比对，且**可现场实时重算**。
- **非公开测评集（只含输入、不含结果）**：**赛前不下发**，现场由评委提供**只含输入、不含结果**的材料，当场检验系统的泛化能力与新增场景的适配成本。

> **本赛题提示**：非公开测评集为**未参与公开集的另一批催收场景与客户样本**，现场提供、只给输入不给答案；要求系统对未见场景能快速适配（改配置优于改代码）。

## 6.3 业务侧自查重点

- 对话环节重点考察**意图识别准确性**与**话术的合规边界**（评委将随机抽轮核对）；
- 合规检测重点考察**红线的漏检与误报**（违规时段、频次超限、虚假承诺、辱骂威胁）；
- 大模型能力不是"调一次 API"，关注 Prompt 设计、规则与大模型的**融合方式**、输出的结构化与稳定性。
