## 二、逐项说明

### 2.1 可运行系统包（Demo 或在线访问链接）

- **内容要求**
  - 支持用户**自主输入催收场景内容**并查看对话与评估报告
  - 七项必选功能须全部可达：多轮催收对话、还款意愿评估、合规红线检测、分期方案协商、情绪感知、人工接管、催收报告
  - **不得**直接基于多个 CSV 做简单 LLM 应用输出，须为 Agent 系统，支持数据导入、解析、分析、解释、决策、可视化完整流程
- **格式要求**
  - 源码 UTF-8 无 BOM，LF 换行；提供容器化或等价一键脚本
  - 若以在线链接形式提交：须在 `manifest.yaml` 与邮件正文写明 URL、可用时间段、账号（如有）
- **命名规范**：`星火队_赛题08_可运行系统包.zip`

### 2.2 源代码与部署说明

- **内容要求**
  1. 环境依赖与版本
  2. **依赖清单**（独立文件，列出全部依赖名与锁定版本）
  3. 数据导入方式（4 张维表 + 5 张事实表 + `schema_relationships.csv` 的关系装载）
  4. **可直接复制执行的启动命令**
  5. 访问地址与默认端口
  6. 合规规则库（`dim_compliance_rule.csv`）与分期模板（`dim_installment_template.csv`）的**配置路径**（须可配置，非硬编码）
  7. 批量运行公开测评集的脚本路径与用法
- **格式要求**：`README.md`（UTF-8）+ `requirements.txt` 或等价依赖清单文件
- **命名规范**：`README.md` / `requirements.txt`（置于提交包根目录）

### 2.3 技术方案说明

- **内容要求**（建议章节）
  1. Agent 架构图：角色划分、编排方式、工具层、记忆层、Skill 层
  2. 数据导入与建模：9 张表的主外键装载与口径统一
  3. 对话管理：多轮催收对话、上下文记忆、意图切换；覆盖提醒、施压、协商、confirm 等典型话术
  4. 还款意愿评估：结合客户画像、逾期信息、历史行为输出**还款意愿评分（0-100）与依据**
  5. 合规引擎：实时识别辱骂、威胁、违规时段（22:00-次日 8:00）、频次超限、虚假承诺等违规
  6. 分期协商策略：基于欠款金额与客户承受能力生成分期方案，支持多轮协商调整
  7. 情绪感知：识别愤怒、焦虑、抵触、配合等情绪并随对话动态更新
  8. 人工接管：触发合规风险或客户强烈拒绝时平滑切换至人工坐席并移交上下文
  9. 催收报告：含还款意愿、建议策略、合规审计、协商记录
  10. 记忆系统、会议与资产管理、工具调用、Skill 管理四项工程能力的实现
  11. 鲁棒性与可解释性设计、合规性设计
- **格式要求**：A4 PDF，≥10.5pt，≤30MB；**须同时提供同名 `.md`**
- **命名规范**：`星火队_赛题08_技术方案.pdf` / `.md`

## 六、通用纪律

1. **严禁使用真实客户 / 企业数据**（金融监管红线）。本赛题数据全部为模拟生成，客户姓名、身份证号、手机号均为脱敏虚构数据；参赛系统的开发、演示、录屏、截图、导出文件与日志中均不得出现真实个人金融信息。
2. **外部大模型调用须脱敏、可审计**。确需调用外部大模型时先完成脱敏（姓名、证件号、手机号、欠款金额）；外部调用的入参、时间、用途须有日志留存，可供评审追溯。
3. **现场须可实时重算，不得预录 / 硬编码结果**。评委将从 `公开测试集答案.csv` 现场抽样，并提供**未参与公开集的另一批催收场景与客户样本**（只给输入、不给答案）；系统须当场给出对话输出、合规判别与报告结论，且对未见场景能快速适配（**改配置优于改代码**）。
4. **引用开源组件须声明 License**。所有使用的开源库须逐条声明名称、版本、License、用途与来源链接。
5. **公开测评集仅用于自测**。不得写入提示词、不得用于预填结果；非公开测评集赛前不下发、现场提供。
6. **法律法规条款不得编造**。政策、法规、条款、标准编号与条文内容不得由模型幻觉生成，更不得作为结论依据。
7. **合规红线必须稳定识别并触发人工接管**。违规时段、频次超限、虚假承诺、辱骂威胁四类红线不得漏检；演示环境需提前自备，现场不提供额外调试时间。
