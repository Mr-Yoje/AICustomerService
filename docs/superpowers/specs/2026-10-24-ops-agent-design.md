# 运营子 Agent 设计

- 状态：现行（已确认）
- 日期：2026-10-24
- 上位规格：`2026-10-24-collection-agent-design.md`
- 范围：把业务查询、报告和规则校验从主控移到运营子 Agent。对外回复、审计和会话副作用与移动前一致。

## 1. 已确认的决策

- 合成一个运营子 Agent，接手画像、欠款、当日联系次数、对话前意愿评分、单客户报告、月度汇总报告、能否外呼、时段与频次、话术审核、人工坐席话术检查，以及发起催收前的外呼门禁和客户快照。
- 主控保留唯一入口、说话人判定、运营意图识别、业务包匹配、案件与会话、发起和结束催收、模式切换、转人工移交包、后置任务。
- 催收子 Agent 继续服务当前客户对话。对话中的检查点一仍由催收子 Agent 直接调用同一份合规引擎。
- 主控按已识别的意图转交。运营子 Agent 不再做运营意图识别。
- 画像、逾期优先级、评分、报告和合规检测的计算函数继续共用。查询与运营侧校验只注册在运营子 Agent 上。

## 2. 入口

运营子 Agent 不创建会话，不切换模式，不调用催收子 Agent。它持有自己的工具注册表，名称为 `ops`。

### 2.1 `lookup`

入参：客户编号。

返回：客户是否存在；优先级最高的贷款类型。没有逾期记录时贷款类型为空。排序与 `loans.prioritize` 相同。

客户不存在时抛出 `ValueError`，消息为 `客户不存在: {客户编号}`。不写入案件或会话。

### 2.2 `answer`

处理主控已经识别的运营意图：查询画像、查询欠款、生成报告、合规问答、失联修复。

入参：意图、原文、客户编号（可空）、当前时间、轨迹、会话编号（可空，供审计）。

缺客户编号的拦截留在主控：查询画像、查询欠款和失联修复在转交前回复「请提供客户编号」。生成报告和合规问答允许没有客户编号。未识别意图由主控回复现有帮助说明，不调用本入口。

客户不存在时抛出 `ValueError`，消息为 `客户不存在: {客户编号}`。

返回字段：回复正文、命中规则、合规结果、意愿评分、意愿等级、建议策略、是否需复核、复核原因。某一意图用不到的字段为空。

回复口径与移动前相同：

- 查询画像：脱敏姓名、年龄、职业、地区、月收入、信用评分、客户等级、意愿分与等级、置信度、贡献最高的三项。需要复核时附复核原因。该客户有上次会话意愿、上次联系或未结承诺时，附在回复末尾。
- 查询欠款：笔数、合计、排序依据、逐笔逾期、优先建议、贷款归属冲突。有冲突时需复核。同一贷款编号有多条时，优先取属于该逾期客户的一条；没有属于该客户的贷款时，仍按最早导入的那条标归属冲突。
- 单客户报告：回复是一段总结（逾期笔数、欠款、最长逾期天数、意愿评分与等级、建议策略），并附完整报告链接 `/reports/{产出物编号}`。意愿评分、等级、建议策略和数据冲突来自报告内容。产出物种类为「催收报告」，正文为带总结段的 Markdown。
- 月度汇总：没有客户编号，或原文包含「本月、汇总、全部、所有、月度」时走汇总。回复是一段总结（催收次数、覆盖客户、正向结果率、意愿分布、合规命中、人工接管、实际还款），并附完整报告链接 `/reports/{产出物编号}`。产出物种类为「汇总报告」，不挂具体案件，由本入口写入。原文含「评估」或「合规审计 / 审计报告」时不走这条，改走下面两种报告。
- 本月催收评估报告：原文含「评估」。统计月份为当前时间所在月。维度是客户。指定一个客户编号且原文不含「全部、所有、全量」时只出该客户；否则出全部客户。每个客户包含催收次数、还款意愿评分与等级、合规审计命中（辱骂、威胁、虚假承诺、违规时段、频次超限，以及库里出现的其他规则）、分期协商次数、人工接管次数、建议策略、催收结果分布。数字只来自通话记录、审计日志、移交包和意愿评分，不编造触达率或还款率。本月没有催收记录时在说明里写明，仍按客户列出。产出物种类为「催收评估报告」。
- 合规审计报告：原文含「合规审计」或「审计报告」。客户范围与评估报告相同。每个客户包含上述规则命中次数和人工接管次数。产出物种类为「合规审计报告」。
- 合规问答：检查点二，动作「外呼」。命中时回复「不可以」及规则编号、类型、内容和处置；有下次可联系时间时写入回复。未命中时回复「可以」及当前时间与当日联系次数。审计场景为「合规问答」。
- 失联修复：原文含「失联、无人接听、未登录」。先查客户画像，再按该客户通话记录统计无人接听次数，并取最近一次 APP 登录时间。回复给出次数、登录情况和修复建议：暂停连续拨打同一号码，改约白天联系，改用短信或 App 消息，请客户本人回拨。不编造电话号码。

### 2.3 `prepare`

入参：客户编号、渠道（外呼 / 客户进线）、业务包名称、门禁规则编号、前置工具及失败策略、当前时间、轨迹、会话编号。

返回：阻断说明（通过时为空）、门禁结果（客户进线时为空）、客户快照。快照字段与催收子 Agent 的 `Snapshot` 相同：画像、逾期、当日联系次数、对话前意愿、降级工具名。

执行顺序：

1. 渠道为外呼时执行检查点二，动作为「外呼」，只启用业务包门禁。写入审计，场景为业务包名称，内容为「发起外呼 {客户编号}」。不通过时返回阻断说明，内容与移动前相同：命中规则、类型、内容、处置；有下次可联系时间时写入说明。不写会话记忆，不结束会话。
2. 客户进线跳过外呼门禁，仍执行前置工具。
3. 按业务包顺序调用前置工具。`get_customer_profile`、`get_overdues`、`get_contact_count_today`、`get_willingness` 分别写入快照对应字段。
4. 调用失败且策略为 `block`：返回阻断说明 `前置工具 {工具名} 调用失败（{原因}），已停止发起`，并写一条检查点为「前置检查」的事件。快照可以不完整。
5. 调用失败且策略为 `degrade` 或 `warn`：把工具名记入快照 `degraded`，继续后续工具。

### 2.4 `review_speech`

入参：话术原文、客户编号（可空）、场景（话术审核 / 人工坐席）、业务包专属规则、改写兜底话术、规范开场模板、当前时间、轨迹、会话编号（可空）。

执行检查点一，写入审计，并生成回复：

- 命中：回复以「[合规拦截]」开头，附规则说明和改写建议。改写先走大模型；候选句再经检查点一且不使用语义判定，通过后采用。失败或大模型不可用时使用业务包兜底改写。命中 R006 或 R009 时，回复里的称谓和带「元」的金额全部去掉，建议改写固定为「请只与客户本人沟通账单，不要提及他人的姓名和欠款。」，不再调用模型改写。转告、向同事透露欠款、联系他家里人，都算这两条规则。模型改写若仍含称谓、金额或「转告」，弃用该候选。
- 未命中：回复为「[合规通过]」加规范开场。

返回：是否通过、回复正文、命中规则、合规结果、是否转人工、是否需复核、复核原因。严重级是否成立由合规结果中的违规等级表达。主管复核待办由主控根据严重级创建。本入口不写对话记录。

## 3. 主控如何调用

运营问答：识别意图后调用 `answer`，把返回字段填入本轮结果。

话术审核：说话人判定为坐席时调用 `review_speech`，场景为「话术审核」。合规结果含严重级时，主控创建种类为「主管复核」的待办。

人工接管：主控收到人工坐席发言后调用 `review_speech`，场景为「人工坐席」。通过后主控把原文记入对话；未通过的话不记入、不发给客户。

发起催收与客户进线开会话，顺序固定：

1. `lookup`。客户不存在时不创建案件。运营入口把 `ValueError` 回复为「处理失败：{异常}，请稍后重试。」
2. 主控用返回的贷款类型匹配业务包。没有贷款类型时用默认业务包。
3. 主控创建案件和会话，校验业务包。前置工具名必须存在于运营子 Agent 的工具注册表。校验失败时主控结束会话，不调用 `prepare`。
4. `prepare`。门禁不通过时，主控把命中规则和下次可联系时间写入会话记忆，结束原因为「外呼门禁拦截」。前置工具按 `block` 失败时不写门禁记忆，结束原因为阻断说明。两种情况都由主控结束会话，并把阻断说明回给调用方。
5. 通过后，主控用返回的快照创建催收子 Agent，会话进入催收对话模式。

结束催收不调用运营子 Agent。

工具调用失败被 `answer` 抛出时，主控回复「处理失败：{异常}，请稍后重试。」空输入和乱码仍由主控在路由阶段兜底。

## 4. 注册表与接口

工具和 Skill：

| 名称 | 类型 | 作用 |
| --- | --- | --- |
| `get_customer_profile` | 工具 | 客户基本信息、近期行为、情绪、还款记录、长期记忆 |
| `get_overdues` | 工具 | 全部逾期及处理优先级 |
| `get_contact_count_today` | 工具 | 指定日期已被联系次数 |
| `get_willingness` | 工具 | 对话前还款意愿评分 |
| `customer_report` | Skill | 单客户催收报告 |
| `summary_report` | Skill | 月度催收汇总报告 |
| `collection_eval_report` | Skill | 本月催收评估报告，单个客户或全部客户 |
| `compliance_audit_report` | Skill | 合规审计报告，单个客户或全部客户 |

`GET /api/registry` 返回三组：`main`、`ops`、`collection:{业务包编号}`。`main` 分组保留，其中没有上表这些工具。`get_overdues` 属于 `ops`。

说明、超时、重试次数和是否启用放在配置 `registry/default`。保存后运营子 Agent 重建注册表。催收子 Agent 的同名配置在新会话创建时套用。停用的工具调用返回「已停用」，并且不再计入 `names()`。

`GET /api/customers/{customer_id}` 通过运营子 Agent 的注册表调用画像、逾期和意愿评分。客户不存在仍返回 404。响应字段不变。

## 5. 测试

现有主控 `handle` 测试的断言保持不变：夜间合规问答命中 R004；坐席威胁话术命中 R002 并生成主管复核；人工接管中的违规话术被拦截；月度汇总回复含「催收次数」；夜间发起催收被拦截并留下下次可联系待办和外呼拦截记录；白天发起后进入催收对话，运营结束后写入 AI 对话记录；查询 C0001 欠款的回复含 O0033；查询 C0002 画像的回复含还款意愿；空输入不进入运营子 Agent。

催收子 Agent 现有测试保持不变。

新增：

- 主控注册表不含第 4 节的六个名称；这些名称在 `ops` 注册表中。
- `prepare` 在门禁失败或前置工具 `block` 时只返回阻断说明，不创建、不结束会话。
- 客户进线的 `prepare` 不产生门禁结果，仍执行前置工具。`degrade` 与 `warn` 把工具名记入 `degraded`。
- 两个随仓业务包对照 `ops` 工具名校验通过。
- 注册表接口含 `ops` 分组，且 `get_overdues` 在该组。

## 6. 明确不做

- 改催收子 Agent 的工具、阶段机和对话中的检查点一调用方式。
- 改合规引擎的判定规则、报告计算口径、后置任务。
- 让运营子 Agent 识别运营意图、创建会话或切换模式。
- 主控、运营子 Agent、催收子 Agent 共用一个工具或 Skill 注册表。
